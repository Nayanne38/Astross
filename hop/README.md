# Apache Hop orchestration

Hop only **sequences, logs and schedules** the pipeline. Every action is a Shell action calling
one step of the standalone Python pipeline, so the project never depends on Hop:

```bash
python -m etl.pipelines.run --mode full --region matopiba            # same thing, no Hop
python tasks.py etl-incremental                                      # daily run, no Hop
```

| Workflow | Actions (each fails the workflow on non-zero exit) |
|---|---|
| `workflows/etl_full.hwf` | extract → transform → data_quality → load → ml_train → ml_forecast |
| `workflows/etl_daily.hwf` | extract_transform (NRT window) → data_quality → load → ml_forecast |

The workflows are generated by `generate_workflows.py`; edit that file and re-run it rather than
editing the XML by hand.

> Status: the `.hwf` files are well-formed XML following Hop's workflow format, but **they have
> not been opened or executed in an actual Hop install on the dev machine yet** (Hop is not
> installed there). The ML actions call `tasks.py train/forecast`, which exist from Phase 5.

## Running with Hop
1. Install Apache Hop 2.x (needs Java 17+).
2. Hop GUI → *Projects* → add project, home = this `hop/` folder (`project-config.json` is read).
3. Set project variables if needed: `PYTHON` (`.venv/Scripts/python` on Windows,
   `.venv/bin/python` on Linux/macOS) and `REGION`.
4. Open `workflows/etl_daily.hwf` and run, or headless:
   ```bash
   hop-run.sh -j calendario-queimadas -r local -f hop/workflows/etl_daily.hwf -p REGION=matopiba
   ```

## Daily schedule (documentation only — no infrastructure is set up)
FIRMS NRT data for a day keeps arriving for a few hours after each overpass, so run once a day
after ~06:00 UTC; the 7-day window re-processes the previous days and replaces them in the DB.

Linux cron (with Hop):
```cron
30 6 * * *  cd /opt/calendario-queimadas && hop/hop-run.sh -j calendario-queimadas -r local -f hop/workflows/etl_daily.hwf >> logs/etl_daily.log 2>&1
```
Linux cron (without Hop):
```cron
30 6 * * *  cd /opt/calendario-queimadas && .venv/bin/python tasks.py etl-incremental >> logs/etl_daily.log 2>&1
```
Windows Task Scheduler (without Hop):
```powershell
schtasks /Create /SC DAILY /ST 03:30 /TN "CalendarioQueimadas-ETL" `
  /TR "cmd /c cd /d C:\path\to\calendario-queimadas && .venv\Scripts\python tasks.py etl-incremental >> data\etl_daily.log 2>&1"
```
Every run writes a row to `etl_runs` (status, row counts, DQ results, error message), so a failed
night is visible in the database and in the log.

Re-run the **full** workflow occasionally (e.g. monthly) so NRT days are replaced by standard
processing (SP) data once FIRMS publishes it and the calibration is refitted.
